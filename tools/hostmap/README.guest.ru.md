# Гостевой хостинг на сайте

Новая версия опубликована10ноября2026 после отдельного подтверждения владельца. Гостевая загрузка и создание комнат включены. Статус проверок записан в guest-progress.md и отчёте.

Открыть https://maps.wc3.uplay2.ru/ из раздела «Захостить карту» общего сайта. Выбрать .w3x/.w3m до32МиБ, нажать «Загрузить карту». После проверки появится название комнаты и кнопка «Создать игру». Комната создаётся только по нажатию; загрузка заранее не занимает хостер.

Войти в пользовательские игры Warcraft и найти указанное имя. Матч запускается голосами `!go` всех играющих людей. Судьи и компьютеры не голосуют. Вход на сайт, Discord и ссылка от бота не требуются. Временная сессия браузера действует24часа; после удаления cookie она теряется. Она не подтверждает ник Battle.net и не даёт права игровой учётки. Для гостевых комнат в этой версии нет выдачи личных команд `!swap`/`!kick` по введённому нику.

Если оба рабочих хостера заняты, карта сохраняется, а создание можно повторить позже. Одна активная/ожидающая комната на сессию, до двух на домашнюю сеть. Пять попыток загрузки за24часа на сессию и IP, не чаще одной в минуту; общий принятый объём1ГиБ. Принятые карты остаются в каталоге до удаления оператором.

Файлы попадают в карантин. Проверка настоящего MPQ, обязательных компонентов карты и нативного GHost проходит в отдельном контейнере без сети и паролей, с лимитами памяти и времени. Простое переименование скрипта в .w3x не делает его картой. Проверка структуры не является гарантией безвредности любой настоящей карты для устаревшего игрового клиента.

## Оператору

Публикация выполняется поэтапно из `/opt/warcraft-iii-online/hostmap`:

```
python3 deploy_guest.py prepare
python3 probe_guest.py
python3 deploy_guest.py publish
```

Первый шаг создаёт резервную копию app/compose/DB, устанавливает страницу с публичным гостевым API выключенным и перезапускает только приёмник/контроллер. Второй запускает закрытый HTTP-приёмник на loopback6130 для проверки реальной цепочки загрузки и создания комнаты. После успешного теста третий шаг включает публичный гостевой API; выполнять только после необходимого подтверждения публикации.

`controller/guest-enabled` проверяется на каждом запросе. Его удаление оператором отзывает гостевой API без перезапуска игровых процессов; существующие игры продолжаются. Возобновление — восстановление контролируемого маркера только после проверки состояния. Порт6130 не открывать наружу;6129 остаётся за Nginx. Остальные виртуальные сайты и порты не менять.

Для старого подтверждённого потока личные ссылки `!upload` переводятся на `/legacy`; они не дают доступа к гостевым заявкам. Данные гостевых сессий, секреты и IP-счётчики не публикуются на GitHub и в рейтинге.

## Карты на сервере
На странице maps.wc3.uplay2.ru сначала доступен список проверенных карт и поиск по названию. Выберите карту, задайте имя комнаты и нажмите «Создать игру». Повторная загрузка файла не требуется. Для новой версии раскройте «Загрузить новую карту».

Перед отправкой сайт сравнивает SHA-256 файла с каталогом. При совпадении использует существующую карту без отправки файла. При прямой повторной загрузке сервер также распознаёт совпадение и удаляет временный файл. Квота хранения считает одинаковые готовые карты один раз. Разные версии с одинаковым названием различаются по содержимому.

Warcraft получает стабильный путь Maps\Download\<код>.w3x/.w3m. Поэтому файл под исходным именем на компьютере может скачаться ещё один раз под серверным именем; содержимое карты бот не изменяет.

Обновление deploy_catalog.py перезапускает только uploads и native broker. Игровые процессы и controller проверяются на неизменность; перед обновлением создаётся резервная копия базы и заменяемых файлов.
