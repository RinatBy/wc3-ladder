# HostMap — пользовательские комнаты Warcraft III 1.29.2

Отдельный общий бот, два рабочих хостера HostMap1/HostMap2. Постоянные комнаты Classic, NewYear, LoD работают независимо. С10ноября2026 доступен гостевой хостинг на сайте без входа и команды `!upload`: выбрать карту, дождаться проверки и нажать «Создать игру». Подробности — README.guest.ru.md. Ниже сохранены игровые команды для совместимости. Одиночный запуск LoD подтверждён пользователем; матч HostMap с несколькими настоящими игроками пока не проверяли.

## Игроку

В чате Battle.net:

```
/w HostMap !maps
/w HostMap !maps Echo
/w HostMap !host КОД_ИЗ_СПИСКА Test1
```

Код нужно скопировать из ответа бота. В пробной версии название комнаты задаётся латинскими буквами, цифрами и пробелами, до 30 знаков.

Открыть пользовательские игры, войти в созданную комнату. Все играющие люди пишут `!go`. Судьи/наблюдатели не голосуют, компьютеры тоже. Все должны скачать карту и подтвердить вошедшую в Battle.net учётку. При изменении состава или слотов готовность сбрасывается. `!start` тоже означает один голос; принудительный старт недоступен.

Если автоматическая проверка ника не прошла, бот подскажет `/w HostMap1 sc` или `/w HostMap2 sc` — написать именно рабочему боту своей комнаты. Повторить `!go` после подтверждения. Штатная проверка GHost также ожидает три измерения пинга после входа.

Создатель управляет только своей комнатой: `!swap 1 2`, `!open 3`, `!close 3`, `!sp`, `!kick НИК`, `!unhost`, `!abort`. `!ping` доступен участникам. Без глобальных банов, прав администратора или управления другими комнатами.

Две комнаты всего, включая начатые матчи, одна на учётную запись. Если оба хостера заняты — дождаться завершения. Лобби имеет тайм-аут ожидания 10 минут. Интервал обработки команд игры — 30 мс. Карта сама должна поддерживать выбранный неполный состав.

## Новые карты

Основной путь — раздел «Захостить карту» на https://wc3.uplay2.ru/ или напрямую https://maps.wc3.uplay2.ru/. Регистрация, Discord и личная ссылка не нужны. Подробности ограничений и эксплуатации — README.guest.ru.md.

Ранее действовавший путь через игровую учётку также сохранён:

В чате Warcraft написать:

```
/w HostMap !upload
```

Открыть личную ссылку от бота, выбрать файл карты и нажать «Загрузить карту». После проверки страница покажет готовую команду создания комнаты. Карта появится в каталоге `!maps`; повторно загружать её для каждой игры не нужно. Адрес приёмника: https://maps.wc3.uplay2.ru/. Без личной ссылки отправка недоступна. Служебный порт 6129 остаётся только на loopback.

Личная ссылка действует 15 минут, подходит для одной попытки отправки .w3x/.w3m до 32 МиБ. Не более пяти ссылок за сутки на аккаунт, не чаще одной в минуту. Ссылка содержит одноразовый секрет — её не публиковать. Игроки получают карту от VDS в лобби Warcraft.

Приёмник не разбирает MPQ и не получает паролей. Отдельная проверка без сети и учёток ограничена памятью/временем; читает нужные части MPQ с ограничениями и выполняет полноценную проверку картой GHost. Проверенные файлы неизменяемые и доступны хостерам только для чтения. Это защищает сервер от ряда классов проблем; безопасность произвольной карты для устаревшего клиента Warcraft не гарантируется.

## Оператору

VDS: `/opt/warcraft-iii-online/hostmap`. Отдельный Compose-проект `warcraft-iii-hostmap`, образ `warcraft-iii-hostmap:trial`. Рабочие TCP-порты 6117 и 6118 опубликованы с разрешения владельца. Исходники также находятся в отдельной ветке `hostmap-trial-20261108` репозитория RinatBy/wc3-ladder; основная ветка сайта не менялась.

```
python3 deploy.py prepare
python3 deploy.py start
python3 finish.py probe
python3 finish.py persist
python3 deploy.py status
```

`prepare` не перезаписывает уже подготовленный Compose. Сверяет хеш патча в образе, создаёт собственные учётки, сохраняет идентичности существующих контейнеров. `start` запускает только новый Compose-проект. `probe` входит отдельной обычной учёткой HostMapProbe, получает каталог, создаёт собственную пробную комнату, проверяет её выдачу сервером и очищает только эту пустую комнату. Проверка не заменяет матч на двух настоящих клиентах.

`finish.py publish` добавляет ровно разрешение TCP 6117–6118. Выполнять после подтверждения владельцем. Не останавливать старые комнаты и не открывать SSH.

Пароли остаются только на VDS: config/credentials.json и workers/*/credentials.json. Не выводить и не копировать эти файлы в отчёты. Для controller/receiver доступны только исходники app/, а не весь корень с закрытой конфигурацией.

Загрузка работает через отдельный vhost Nginx, сертификат Let's Encrypt с автоматическим продлением и перезагрузкой Nginx. Фоновая служба проверки: `warcraft-iii-hostmap-maps.service`; основной автозапуск: `warcraft-iii-hostmap.service`. Для systemd на хосте существует группа hostmap-data с GID10005, совпадающим с общей группой данных в контейнерах.

Проверка загрузки без создания или остановки игр:

```
python3 verify_uploads.py
```

Она использует только отдельную обычную учётку HostMapProbe, загружает уже разрешённую Echo Isles, проверяет одноразовость ссылки, публикацию, службу и продление сертификата, неизменность запущенных игровых процессов. Отчёт на VDS: `upload-probe-verified.json`. Не запускать часто: на тестовую учётку действуют те же ограничения загрузки.

При повторном применении TLS использовать только `enable_uploads.py activate`; `prepare-http` предназначен для первоначального выпуска сертификата и временно заменяет собственный HTTPS-vhost HTTP-конфигурацией. Игровые хостеры не перезапускать во время матчей.

## Проверки

```
python3 -m unittest discover -s . -p 'test_*.py'
g++ -std=c++11 test_ready.cpp -o test-ready && ./test-ready
```

Dockerfile запускает C++-проверку голосования перед сборкой патча. Результат сборки на VDS: build.exit; журналы build.log. В Windows локальная компиляция голосования проверялась MSVC. Native GHost компилируется под Linux на VDS.
